# 催催｜会中干预型会议助手

催催持续理解会议里正在发生的讨论，在偏题、重复、争论失焦和预计超时时及时提醒，并帮助团队把分歧收敛为决定、把决定落实到负责人和下一步。

公网演示：<https://cuicui.iotaceti.top>

访问站点时会先进入全站密码页。密码由演示负责人单独提供，不写入仓库或文档。验证通过后，当前浏览器会话可直接使用全部演示功能，不设置额外的体验次数或时长限额。

## 两个入口

### 开始演示会议

首页的“开始演示会议”会播放一场约 120 秒的“会员日活动上线评审”。团队需要确认满减规则、发布节奏、异常阈值和负责人，场景不依赖额外背景说明。

- `00:00–00:29`：运营、产品和研发依次给出满减规则、用户路径与上线风险，催催在右侧记录议题进展，不打断正常讨论。
- `00:30–00:42`：讨论连续转向团建和餐厅。第一次偏离只静默记录，第二次升级为轻提醒，主持人随后把话题拉回上线条件。
- `00:50–01:19`：研发提出灰度与回滚条件，业务负责人连续打断。前两次只记录，第三次升级为加强提醒；时间进入尾段时，催催同步记录预计超时风险。
- `01:28–01:59`：团队确认内部灰度、全量时间和暂停阈值，随后明确监控、推送确认与页面验收负责人。

字幕、提醒和时间预测会沿会议进度逐步出现。会议结束后，页面根据本次讨论展示会议质量雷达、关键节点、决定和行动项。

### 立即体验

“立即体验”提供两种使用方式：

1. **单人体验**：一个人使用麦克风发言，通过页面上的角色切换模拟多人讨论。适合快速体验实时听写、提醒和评分链路。
2. **多人体验**：主持人创建会议并分享 6 位加入码或邀请链接，其他成员用自己的姓名和角色加入。主持台与参与端都会看到全场字幕、参会人列表、会议进度和催催提醒。

单人与多人模式都使用科大讯飞 IAT WebSocket 直连听写。如果浏览器权限、网络或讯飞连接失败，页面会明确告知原因，不会改用另一条高延迟识别链路。

多人模式适合线下同室会议，或参会者已经通过其他会议软件通话的远程场景。催催当前不传输远端通话声音；每台设备负责把当前成员的发言转成带身份的字幕。会议开始后，主持人与参会者页面都会自动尝试开启麦克风，也可以随时手动关闭或重试。同处一室时建议佩戴耳机或只保留当前发言者的麦克风，避免重复收音。

## 干预层级

催催不会让每个信号都弹出提醒，而是按影响逐级处理：

- **L0 静默记录**：首次偏题、正常议题进展、决定和行动项只进入右侧记录。
- **L1 轻提醒**：重复出现或需要主持人关注时，以不遮挡会议的浮层提示，并在数秒后自动收起。
- **L2 加强提醒**：连续打断、重要分歧或紧迫时间风险升级后，以更醒目的浮层和倒计时提示，但仍不会阻断会议操作。

主持人可以在完整记录中查看依据，并选择采纳建议、放入停车场或忽略。参与端同步看到提醒内容，但会议决策操作仍由主持人完成。

## 会议数据如何流动

1. 演示会议录音按发言时间轴播放；实时体验则直接接收当前麦克风输入。
2. 每句发言结束后形成稳定字幕，并保留发言者身份和时间。
3. 新字幕连同会议议题、剩余时间和已有提醒进入会中分析。
4. 干预规则决定信号进入静默记录、轻提醒还是加强提醒。
5. 会议结束时使用本次转写和干预记录计算评分，并整理决定与行动项。

演示录音和分析产物只在输入哈希一致时复用；台词、音频或会议配置变化后需要重新生成对应产物。

## 本地运行

依赖通过 `mise` 隔离，不需要全局安装 Node/npm 包。

```powershell
$env:MISE_DATA_DIR = Join-Path $PWD '.mise-data'
mise trust
mise install
mise run install
mise run dev
```

访问 <http://localhost:3000>。将 `.env.example` 复制为 `.env.local`，并设置本地的 `SITE_ACCESS_PASSWORD`、会话签名参数和所需服务凭据；不要提交真实密钥。

```powershell
mise run check
mise run build
mise run smoke
mise run room-verify
```

重建录音和验证会议链路是显式任务，会调用外部服务，仅在会议数据变更时执行：

```powershell
mise run audio-generate
mise run audio-verify
```

`mise run smoke` 和 `mise run audio-verify` 都要求另一个终端中的本地 3000 端口服务保持运行。

## 部署

临时部署分支为 `dev`。推送 `dev` 后，GitHub Actions 会：

1. 在 GitHub 托管 runner 上类型检查、构建并发布不可变 SHA 镜像到阿里云 ACR；
2. 由名称/标签为 `cuicui-deploy` 的专用自托管 runner 校验服务器预置 Compose 配置，并使用服务器已有 ACR 凭据拉取镜像；
3. 在 `/srv/docker/cuicui` 启动容器，并只映射 `127.0.0.1:8476`；房间、成员和转写持久化到该目录下的 `data/`；
4. 验证容器健康与公网 TLS/反向代理链路，失败时自动尝试回滚；
5. 只清理同一 Cuicui ACR 仓库的旧镜像，并保留最近一个健康版本作为回滚点。

演示讲解词见 [DEMO_GUIDE.md](./DEMO_GUIDE.md)。

## 主要目录

```text
app/
├─ access/                 # 全站访问密码页
├─ api/                    # 讯飞、会中分析、报告与访问验证
├─ join/                   # 加入码入口与移动端参与页面
├─ meeting-app.tsx         # 演示会议、单人体验、多人主持台与会后报告
├─ participant-view.tsx    # 多人会议参与端、共享字幕与提醒
├─ intervention-routing.ts # L0/L1/L2 干预分级与优先级
├─ room-types.ts           # 主持端、参与端与 API 共用的房间协议
├─ live-transcriber.ts     # 讯飞 40ms 音频帧直连，失败明确报错
└─ server/                 # 全站 Cookie 验证与服务端访问控制
public/demo/               # 演示录音、manifest 与运行记录
scripts/                   # 音频生成、链路验证与公开 API 检查
```

接口依据：[科大讯飞流式语音听写](https://www.xfyun.cn/doc/asr/voicedictation/API.html)、[OpenRouter TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts)。
